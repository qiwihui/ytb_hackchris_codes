# 撤销一个 7702 委托

## 怎么做

签一笔新授权，`address = 0x000…000`，作为类型 4 tx 发出去。EVM 在上链时把 EOA 的 code 清掉。下一次再调这个 EOA，行为退化成"无代码 EOA"——发 ETH 转账还能成，所有非空 calldata 静默返回（`extcodesize(EOA) == 0`）。

协议层就给你这些。

## 撤销**不会**做的事

1. **存储不清。** EIP-7201 命名空间下写过的槽**仍然在那**。如果你后面又委托回同一个合约，你继承了旧的 `nonce`、旧的会话密钥、旧的所有东西。如果你委托到 v2 但命名空间字符串一样，你也会继承——这正是 `EOADelegate` 给命名空间字符串带版本号的原因。
2. **在飞的会话密钥签名不会被烧掉。** 一旦会话密钥签名离开了你的设备，**在撤销上链之前**任何人都可以拿来调 `executeBySession`。撤销上链后，EOA 已经无代码，这个调用在 EVM 层就 revert。但从"你广播撤销 tx"到"撤销被打包"之间的窗口，**足够一个有备而来的 relayer 用一次**。两种缓解：
   - 给会话密钥加一个 epoch（见 `session-key-design.md`），在发撤销之前把 epoch++，并和撤销打包成一笔。
   - 走 flashbots / 私有 mempool 发撤销，把窗口压到不可见。
3. **其它链上的授权不会被撤销。** 每条链的 code 各自独立。如果你当初用 `chain_id = 0` 签（**别**这么做），你得逐链撤销。

## 更安全的"轮换"模式

比裸撤销更稳的两步走：

1. 对每一把活跃的 session key 调 `removeSessionKey(...)`（或者 bump 一个 epoch）。
2. 签一笔新的 7702 授权，**指向一个新委托**（或新版本），用**新命名空间字符串**——旧存储从新代码的视角变得不可达。

## demo

`demos/05-revoke-delegation.sh` 先撤销，再前后各打印一次 `eth_getCode(EOA)`——观众肉眼看到从 `0xef0100…` 回到 `0x`。
